# web/webui/src/app — how this package hangs together

The FSD **app layer**: the application-wide providers, and nothing else. `index.ts` exports one
symbol, `Providers`, and it has one importer — `web/webui/app/routes/__root.tsx`. There are no
tests and no stories here.

Not to be confused with `web/webui/app` (no `src`), the entry point and the route files. That
directory has no guide of its own; what concerns the wiring is described below.

## Layout

| File | Role |
|---|---|
| `index.ts` | the public contract: `Providers` |
| `providers.tsx` | the module-level `QueryClient` and the provider tree |

`web/webui/app`:

| File | Role |
|---|---|
| `main.tsx` | rsbuild entry: `StrictMode` → `RouterProvider` on `#app`; imports `styles.css` |
| `router.tsx` | `getRouter()` and the `Register` augmentation that types the router |
| `routes/__root.tsx` | root route; its component is `<Providers><Outlet /></Providers>` |
| `routes/_sidebar/route.tsx` | pathless layout: `AppLayout` (`@/widgets/sidebar`) around `<Outlet />` |
| `routes/_sidebar/*.tsx` | one page each: a component from `@/pages/*` plus `staticData.title` |
| `routeTree.gen.ts` | generated by TanStack Router, committed — never edit |
| `styles.css` | Tailwind import, fonts, design tokens, global and third-party overrides |

## Two directories named `app`

- `src/app` is a layer like any other: reached as `@/app` (`@/*` maps to `./src/*` in
  `tsconfig.json`), imports only from layers below it.
- `web/webui/app` is owned by the tooling. `rsbuild.config.ts` points `source.entry` at
  `./app/main.tsx` and the TanStack Router plugin at `./app/routes` / `./app/routeTree.gen.ts`
  (`tsr.config.json` repeats the two paths for `bun run generate-routes`). It imports **into**
  `src` and no module in `src` imports it back. The one outside consumer is
  `.storybook/preview.tsx`, which imports `../app/styles.css`.

`biome.json` lints both under one override (`src/app/**`, `app/**`): every slice is imported
through its barrel, never a file inside it. `src/shared/**` and the other layers are forbidden
from importing `@/app` at all.

`getRouter()` sets `defaultNotFoundComponent` to `NotFound` from `@/pages/not-found`, preloads on
`intent` with `defaultPreloadStaleTime: 0`, and turns on scroll restoration and view transitions.

Route files stay thin — a component, `staticData`, at most `validateSearch` (`operations`). The
title in `staticData` is read by `useStaticData` in `shared/utils`. No route has a `loader` or
`beforeLoad`.

## The provider tree

```tsx
<QueryClientProvider client={queryClient}>
    <LiveUpdates />
    <ThemeProvider>
        <TooltipProvider>
            <ConfigProvider>{children}</ConfigProvider>
            <Toaster />
        </TooltipProvider>
    </ThemeProvider>
</QueryClientProvider>
```

| Node | From | Needs | Gives |
|---|---|---|---|
| `QueryClientProvider` | `@tanstack/react-query` | — | the one `QueryClient`, default options |
| `LiveUpdates` | `@/shared/live` | the query client | the `/api/live` connection; renders `null` |
| `ThemeProvider` | `@/shared/theme` | — | `useTheme`, which throws outside it |
| `TooltipProvider` | `@/shared/ui/tooltip` | — | the Radix tooltip provider, `delayDuration` 0 |
| `ConfigProvider` | `@/entities/config/config` | the query client | a gate on `/api/config` |
| `Toaster` | `@/shared/ui/toast` | — | the sonner outlet for `toast(...)` |

What the placement decides:

- **`QueryClientProvider` is outermost** because `LiveUpdates` calls `useQueryClient` and
  `ConfigProvider` calls `useQuery`. The client is a module constant, so it survives re-renders
  and StrictMode remounts. It carries no `defaultOptions`; tuning lives in each query hook.
- **`ConfigProvider` gates only `children`.** While `useConfig` is pending it renders
  `ConfigLoading`, on error `ConfigError`, and the routed tree only after success. Nothing under
  `<Outlet />` mounts before the configuration has loaded.
- **`LiveUpdates` and `Toaster` sit outside that gate.** The live connection opens while the
  configuration is still loading, and stays open if it failed; toasts can show in those states too.
- **`ThemeProvider` wraps the routed tree**, so `widgets/sidebar/app-sidebar-theme.tsx` (the only
  `useTheme` caller) is always inside it. The `.dark` class itself lives on `<html>`, outside React.

`Providers` is mounted by the root **route**, not by `main.tsx`, so `RouterProvider` is above it
and `getRouter()` passes no `context`. The query client is reachable only through React context
below `__root` — a route loader could not use it as things stand.

## What mounting `Providers` does to the backend

- **`GET /api/config`** — `useConfig` (`getApiConfigOptions()` with infinite `staleTime` and
  `gcTime`): once it has succeeded it is never stale, so later `useConfig()` calls in entities
  and widgets read the cache entry instead of refetching. Backend:
  `internal/application/webui/get_config/AGENTS.md`.
- **`GET /api/live`** — `LiveUpdates` calls `liveStream.retain()` for as long as it is mounted.
  Backend: `internal/application/webui/stream_updates/AGENTS.md`, which notes that a connected
  client is what turns the collectors on.

`LiveUpdates` only subscribes; **what** gets invalidated is in `shared/state/invalidate.ts` —
the metrics prefix on every operations batch, and on a reconnect metrics with
`refetchType: 'all'` plus the operations prefix. Add a live-refreshed query there, not here.

`StrictMode` in `main.tsx` mounts effects twice in dev. `retain` is reference-counted and a
released connection lingers for `LINGER_MS` (1 s, `shared/live/stream.ts`), so the remount reuses
the connection instead of opening a second one.

Both requests go through `shared/api/client.ts`, whose `baseUrl` is the `API_URL` define from
`rsbuild.config.ts`, falling back to the page origin.

## What must change together

- **A new route file** regenerates `routeTree.gen.ts`. On build, the `route-manifest` plugin in
  `rsbuild.config.ts` extracts its `fullPaths` into `routes.json`, and the Go static handler
  answers 200 or **404** for the SPA shell from that list — see `internal/controller/AGENTS.md`.
- **Theme constants.** `shared/theme/theme-script.ts` is injected into `<head>` through
  `html.tags` and sets `.dark` on `<html>` before the bundle runs; `ThemeProvider` toggles the
  same class later. Its literals repeat `shared/theme/constants.ts` by hand, and `styles.css`
  keys on the same names (`@custom-variant dark`, `.dark`, `.theme-transition`).
- **The mount id.** `main.tsx` looks up `#app` and throws without it; the id comes from
  `html.mountId` in `rsbuild.config.ts` via `index.html`, and `styles.css` sizes `#app`.

## Storybook does not use `Providers`

`.storybook/preview.tsx` wraps each story panel in its own `ThemeProvider` + `TooltipProvider`
and nothing else: no query client, no live connection, no config gate, no `Toaster`. Stories are
collected from `src/shared/ui/**` and `src/widgets/**` (`.storybook/main.ts`), so a new provider
added here does not reach them — add it to the preview too if a UI-kit component starts to need
it.
